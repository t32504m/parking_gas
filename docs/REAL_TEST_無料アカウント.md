# 本物の GAS での試験（無料の Google アカウント）

この手順書は、上から順に、書いてあるとおりに進めれば済むように書いてあります。
当日に行うことは、次の3つだけです。

1. 試験用の Google アカウントを作る（0章）
2. GAS にプロジェクトを置く（1〜4章）
3. 試験を実行して、結果を書く（5〜8章）

- この試験では、住民（利用者）も画面から予約できる設定にします（`residentBooking: true`）。予約の確認の入口（`residentLookup`）も開けます。試験の後で、必ず閉じます（6章）。
- 試験は**2日に分けます**。1日目に 0〜5章の T01〜T15 を行い、2日目の朝に T12（夜中のトリガーの確認）と 6章の片付けを行います。
- 所要時間の目安：1日目が3〜4時間、2日目が30分です。
- 本番の公開ではありません。本番の台帳・本番の GAS プロジェクトには、何も触りません。

## 0. 試験用の Google アカウントを作る

1. パソコンの Chrome で、ほかの Google アカウントからログアウトするか、Chrome の右上の人の絵から「ゲスト」または新しいプロファイルを開く。
2. https://accounts.google.com/signup を開き、画面の案内に従ってアカウントを作る。
   - 名前の例：`駐車場 試験`
   - 「自分用」を選ぶ（「仕事用・ビジネス用」は選ばない）。
   - アカウントのメールアドレス（`〇〇〇@gmail.com`）とパスワードは、紙に控える。この文書や結果のファイルには書かない。
3. 作ったアカウントでログインしたまま、次の章へ進む。以後、1〜4章は全て、このアカウントで行う。

## 1. 準備

### 1-1. スプレッドシート（台帳）を作る

1. https://sheets.google.com を開き、「空白のスプレッドシート」を押す。
2. 左上の「無題のスプレッドシート」を押し、名前を **`駐車場予約 台帳（無料アカウント試験）`** にする。
   - 名前に「試験」の2文字が入っていることが大事です。試験用のスクリプト（`TestSeed.gs`）は、台帳の名前に「試験」が入っていないと動きません（本番の台帳を守るため）。
3. メニューの「ファイル」→「設定」を開き、「全般」の「タイムゾーン」を **「(GMT+09:00) 東京」** にして、「設定を保存」を押す。
4. ブラウザのアドレスバーの URL を見る。`https://docs.google.com/spreadsheets/d/〇〇〇/edit…` の **`〇〇〇` の部分（`/d/` と `/edit` の間）** が、スプレッドシートID です。これをコピーして、メモ帳などに貼っておく（2章で使う）。
5. 共有の設定は変えない（右上の「共有」は押さない）。

シート（予約・割当て・通知・操作履歴・使用禁止・予約（保管）・割当て（保管）・通知（保管））は、3章の `setup_run` で自動的に作られます。手で作りません。

### 1-2. GAS プロジェクトを作る

1. https://script.google.com を開き、左上の「新しいプロジェクト」を押す。
2. 左上の「無題のプロジェクト」を押し、名前を **`駐車場予約（無料アカウント試験）`** にして、「名前を変更」を押す。
3. 左の歯車（「プロジェクトの設定」）を押す。
4. **「「appsscript.json」マニフェスト ファイルをエディタで表示する」にチェックを入れる。**
5. 同じ画面に「タイムゾーン」の欄があれば、**「(GMT+09:00) 日本標準時」**（または「東京」）を選ぶ。欄が無くても、次の 1-3 で貼る `appsscript.json` に `"timeZone": "Asia/Tokyo"` が書いてあるので、日本時間になります。T02 で確かめます。
6. 左の `< >`（「エディタ」）を押して、エディタに戻る。

### 1-3. ファイルを貼る

## 2. スクリプト プロパティ（設定）を入れる

1. 左の歯車（「プロジェクトの設定」）を押し、画面のいちばん下の「スクリプト プロパティ」まで進む。
2. 「スクリプト プロパティ」の説明の文の下にある「スクリプト プロパティを追加」を押して、次の5つを1つずつ入れる。ボタンが見当たらないときは、下の「ボタンが無いとき」の方法で入れる。「プロパティ」に名前、「値」に値を入れる。
3. 5つ入れたら、「スクリプト プロパティを保存」を押す。

| プロパティ | 値 |
|---|---|
| `SPREADSHEET_ID` | 1-1 の手順4でコピーしたスプレッドシートID（`/d/` と `/edit` の間の文字だけ） |
| `ADMIN_INVITES` | 下の「ADMIN_INVITES の例」 |
| `CONTACT_NOTE` | `理事会事務局 試験（電話 000-0000-0000）` |
| `TERMS` | `（試験）利用約款の本文は、本番で入れます。` （住民の画面の下に「利用約款」が出るかを見るため。D-032） |
| `RULES` | 下の「RULES（そのまま貼る）」 |

### ボタンが無いとき（エディタから入れる）

「スクリプト プロパティを追加」が出ないときは、次の方法で入れます。

1. エディタの左の「ファイル」の横の「＋」→「スクリプト」で、`TmpProps` という名前のファイルを作る。
2. 中身を全て消して、下を貼る。`'ここに…'` の4か所を、下の表の値に置き換える（前後の `'` は消さない）。`RULES` は、下の「RULES（そのまま貼る）」の1行を、そのまま `'` と `'` の間に貼る。

```
function tmpSetProps() {
  PropertiesService.getScriptProperties().setProperties({
    SPREADSHEET_ID: 'ここにスプレッドシートID',
    ADMIN_INVITES: 'ここに ADMIN_INVITES',
    CONTACT_NOTE: '理事会事務局 試験（電話 000-0000-0000）',
    TERMS: '（試験）利用約款の本文は、本番で入れます。',
    RULES: 'ここに RULES'
  });
  Logger.log(JSON.stringify(Object.keys(PropertiesService.getScriptProperties().getProperties())));
}
```

3. 保存し、関数に `tmpSetProps` を選んで「実行」を押す（初めてなら、3章の手順4と同じ許可が出る）。
4. 実行ログに `["SPREADSHEET_ID","ADMIN_INVITES",…]` が出たら、入っています。歯車の画面を開き直すと、一覧にも出ます。
5. **`TmpProps` のファイルは、すぐに消す**（「⋮」→「削除」）。パスコードがそのまま書いてあるためです。

### ADMIN_INVITES の例

管理者を2人登録します（T06 で、2人が同時に操作するため）。形は `メール,氏名,パスコード` で、2人の間を `;` で区切ります。

```
kanri1@example.jp,試験 管理一,tk7m-q2wp-1x9r;kanri2@example.jp,試験 管理二,pv3n-8hza-4c6e
```

- メールは、管理者の画面で入れる「名前の代わり」です。届くメールアドレスでなくてもかまいません。
- パスコードは8文字以上です。この例のままでも試験はできますが、この文書は人に見られるので、**自分で決めたものに替えることを勧めます**。替えたパスコードは紙に控え、結果のファイルには書きません。
- `setup_run` を実行すると、このプロパティは自動で消えます（パスコードの平文を残さないため）。

### RULES（そのまま貼る）

```
{"capacityPerSlot":2,"maxQuantityPerRequest":1,"residentBooking":true,"residentLookup":true,"residentLeadDays":0,"residentViewMonths":1,"viewMonths":2,"archiveAfterDays":60}
```

それぞれの意味（`docs/SETUP.md` の付録、`src/Config.gs` の `DEFAULT_RULES`）：

| 項目 | この試験の値 | 意味 |
|---|---|---|
| `capacityPerSlot` | 2 | 1コマに入れる台数。本番と同じ。「残り1台」の状態を作りやすい |
| `maxQuantityPerRequest` | 1 | 1回の予約で使える台数。本番と同じ |
| `residentBooking` | **true** | 住民が画面から予約できる。**試験の後で false に戻す** |
| `residentLookup` | **true** | 予約番号と電話番号の下4けたで予約を確かめる入口を開ける。**試験の後で false に戻す** |
| `residentLeadDays` | 0 | 住民の画面に、今日から見せる（本番は5日後から）。当日のコマで試せるようにする |
| `residentViewMonths` | 1 | 住民の画面に見せるのは、今日から1か月先まで |
| `viewMonths` | 2 | 管理者が受け付けるのは、今日から2か月先まで |
| `archiveAfterDays` | 60 | 利用日が60日より前の予約を、保管のシートへ移す。本番と同じ |

`setup_run` を実行すると、`RULES` は、書かなかった項目（`cutoff` など）も含めた形に書き直されます。それで正しい動きです。

## 3. 初期設定（`setup_run`）を実行する

1. エディタの左のファイルの一覧で、**`Setup.gs`** を押して開く。
2. 上の「実行」ボタンの右にある、関数の選択（初めは `setup_run` などが出ている）で、**`setup_run`** を選ぶ。
3. 「実行」を押す。
4. 初めての実行では「承認が必要です」が出る。次の順に進む。
   1. 「権限を確認」を押す。
   2. 試験用のアカウントを選ぶ。
   3. 「このアプリは Google で確認されていません」と出たら、左下の「詳細」を押し、「駐車場予約（無料アカウント試験）（安全ではないページ）に移動」を押す。自分で作ったスクリプトなので、問題ありません。
   4. 許可を求める項目の一覧が出る。「すべて選択」があれば押し、「続行」または「許可」を押す。
5. 下の「実行ログ」に `{"status":"OK","admins":2,…}` が出れば成功です。
   - `SPREADSHEET_ID が設定されていません` と出たら、2章の `SPREADSHEET_ID` を確かめる。
   - `管理者の設定が不正です` と出たら、`ADMIN_INVITES` の形（`,` と `;`、パスコードが8文字以上か）を確かめて、入れ直してから、もう一度実行する。
6. 台帳のスプレッドシートを開き、下のシートの見出しに「予約」「割当て」「通知」「操作履歴」「使用禁止」「予約（保管）」「割当て（保管）」「通知（保管）」があることを見る。
7. GAS のエディタの左の時計の絵（「トリガー」）を押し、`job_processNotifications`（毎日1回、17時〜18時。D-030）と `job_archiveLedger`（毎日、午前3時〜4時）の2つがあることを見る。

## 4. ウェブアプリとして公開する（1回だけ）

**公開（「新しいデプロイ」）は、この章で1回だけ行います。** 「新しいデプロイ」を押すたびに、別の URL ができます。本番では URL を QRコードで配るので、URL を変えない練習も兼ねます（`docs/SETUP.md` 4〜5章、`docs/検討-2026-11-09-安全と構成.md` 7章）。
以後の更新は、T13 のとおり「デプロイを管理」→「編集」だけで行います。

1. エディタの右上の **「デプロイ」→「新しいデプロイ」** を押す。
2. 「種類の選択」の歯車を押し、**「ウェブアプリ」** を選ぶ。
3. 次のように入れる。
   - 説明：`試験 1`
   - 次のユーザーとして実行：**自分（試験用のアカウントのメールアドレス）**
   - アクセスできるユーザー：**全員**
4. 「デプロイ」を押す。
5. 出てきた「ウェブアプリ」の URL（`https://script.google.com/macros/s/〇〇〇/exec`）を「コピー」して、`real-test-results/結果.md` の「利用者用 URL」の欄に貼る。
   - 管理者用 URL は、その末尾に `?page=admin` を付けたもの（`…/exec?page=admin`）。
   - 同じ画面の「デプロイ ID」も、結果.md の欄に貼る。
6. 「完了」を押す。
7. 以後、**「新しいデプロイ」は押しません。** 末尾が `/dev` の URL（「デプロイをテスト」で出るもの）は、住民役の端末では使いません。

スマートフォンに URL を送るには、自分あてのメールか、メッセージのアプリで送ります。

### うまく開けないとき

| 出たもの | 原因 | 直し方 |
|---|---|---|
| 「現在、ファイルを開くことができません」 | ブラウザで、複数の Google アカウントに同時にログインしている（GAS のウェブアプリは、これで開けないことがよくある） | シークレット ウィンドウ（Ctrl+Shift+N）で開く。または、試験用のアカウントだけでログインしたプロファイルで開く |
| 「スクリプト関数が見つかりません: doGet」 | デプロイした版に `doGet` が入っていない（`Web` のファイルが保存される前にデプロイした、または貼り損ね） | `Web` のファイルの先の方に `function doGet(e) {` があるか見て、保存する。「デプロイ」→「デプロイを管理」→ 鉛筆の絵（編集）→「バージョン」で「新バージョン」→「デプロイ」。**「新しいデプロイ」は押さない**（URL が変わる） |
| デプロイの画面の「ライブラリ」の URL を開くと「ライブラリ … へのアクセス権がない」 | その URL は、このプロジェクトをほかのスクリプトから使うためのもの。この試験では使わない | 気にしなくてよい。開くのは「ウェブアプリ」の URL（末尾が `/exec`）だけ |
| QR から住民の画面を開くと、どのブラウザでも、プライベートモードでも「ファイルを開くことができません」 | プライベートモードには Google のログインが無いので、複数ログインだけでは説明できない。いちばん疑わしいのは QR の URL の形（アドレス欄から写すと `/macros/u/1/s/…` のようにログインの番号が入り、ログインしていない端末では開けない。`/dev` で終わる URL も、編集できる人しか開けない） | QR には、デプロイの画面の「ウェブアプリ」の URL（`/macros/s/…/exec`、`/u/数字/` が無い）を入れる。複数ログインの端末のために、画面を GAS の外に置く（D-034・D-035、`docs/STATIC_PAGES.md`）。下の T03b で確かめる |
| 大学・会社のアカウントで開けない | 組織の設定で、外のウェブアプリが止められていることがある | 試験では、個人の Google アカウントか、未ログイン（シークレット ウィンドウ）で開く |

## 5. 試験項目

それぞれの試験には、番号（T01〜T16）・手順・期待する結果・記録する欄があります。
結果は、7章の表（`real-test-results/結果.md` にコピーしたもの）に、○（期待どおり）・×（違った）・－（できなかった）と、記録する値を書きます。
期待と違ったときは、そこで止めずに、起きたことと画面の写真（スクリーンショット）を残して、次へ進みます。写真の名前は `T03-1.png` のように、試験の番号で始めます。

試験で入れる名前は、何の試験か分かるように、試験ごとに決めた名前を使います（例：T03 は `試験 住民一`）。

### T01 プローブ（エミュレータの仮定の確認。別のプロジェクトで行う）

製品とは**別の、使い捨ての GAS プロジェクト**で行います。このプロジェクトでは、デプロイを何回作ってもかまいません。

1. https://script.google.com で「新しいプロジェクト」を作り、名前を `駐車場 プローブ（使い捨て）` にする。

## 8. 結果を返すときの形

`parking-gas` フォルダの中に、次の形でファイルを置きます。フォルダ名は、半角の `real-test-results` です。

```
parking-gas/
  real-test-results/
    結果.md                ← 7章の表に書き込んだもの（文字コード UTF-8）
    probe/
      editor.json          ← T01 手順5
      trigger.json         ← T01 手順6
      web-a-owner.json     ← T01 手順8
      web-a-other.json
      web-b-other.json
    measure/
      0年.txt              ← T10・T11 の testSeed_measure の実行ログ（全てコピーして貼る）
      1年.txt
      3年.txt
      保管後.txt
    logs/
      setup_run.txt        ← 3章の実行ログ（あれば）
      job_archiveLedger.txt ← T11 の実行ログ
      testSeed_status.txt  ← T02・T14・6章の実行ログ（何回分でも、続けて貼る）
    screens/
      T03-1.png など       ← 写真。名前は試験の番号で始める
```
