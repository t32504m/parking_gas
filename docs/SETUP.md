# 初期設定・公開・更新の手順（運用担当者向け）

本番・検証・デモは、**それぞれ別のスプレッドシートと別の GAS プロジェクト**で用意します（要件7.2）。
以下は1つの環境の手順です。環境ごとに繰り返してください。

## 1. スプレッドシートを用意する

1. Google ドライブで新しいスプレッドシートを作る。名前の例：`駐車場予約 台帳（本番）`
2. 「ファイル > 設定」でタイムゾーンを「(GMT+09:00) 東京」にする。
3. アドレスバーの `https://docs.google.com/spreadsheets/d/〇〇〇/edit` の `〇〇〇` 部分（スプレッドシートID）を控える。
4. 共有は**運用担当者だけ**にする（一般公開しない：要件9）。

シート（予約・割当て・通知・操作履歴・使用禁止、と保管用の「予約（保管）」「割当て（保管）」「通知（保管）」）は、手順3の初期設定で自動的に作られます。手で作る必要はありません。

## 2. GAS プロジェクトを用意する

1. https://script.google.com で「新しいプロジェクト」を作る。名前の例：`駐車場予約（本番）`
2. 「プロジェクトの設定」で
   - タイムゾーン：`(GMT+09:00) 日本標準時`
   - 「appsscript.json マニフェスト ファイルをエディタで表示する」にチェック
3. `src/` の全ファイルをプロジェクトに作る（同じ名前で）。
   - `.gs`：Config, Ledger, Booking, AdminApi, Notify, Setup, Web, Block, Sheet, Archive（GAS では同じ名前のファイルを作れないため、管理者の処理のスクリプトは `AdminApi`。HTML の `Admin` とは別）
   - `.html`：Index, Admin, Styles, Common
   - `appsscript.json` は内容を置き換える
   - clasp を使う場合は `clasp push`（`.clasp.json` の `rootDir` を `src` にする）

## 3. 設定値を入れて初期設定を実行する

「プロジェクトの設定 > スクリプト プロパティ」に次を追加する。

| プロパティ | 値 | 必須 |
|---|---|---|
| `SPREADSHEET_ID` | 手順1-3で控えたID | 必須 |
| `ADMIN_INVITES` | `メール,氏名,パスコード` を `;` で区切って並べる。例：`kanri@example.jp,山本 和子,ahx7-2kq9-pe3m` | 初回は必須 |
| `CONTACT_NOTE` | 画面に出す相談先。例：`理事会事務局（電話 0X-XXXX-XXXX）`。満車のときや結果が分からないときの案内に使う | 強く推奨 |
| `RECEPTION_HOURS` | 住民の画面の、電話の受付時間の文。省略すると `受付時間　AM 10:00〜12:00　PM 14:00〜19:00`（D-032） | 任意 |
| `TERMS` | 利用約款の本文（改行も、そのまま出る）。空なら、住民の画面に「利用約款」を出さない（D-032） | 本番では必須 |
| `RULES` | 運用ルール（JSON）。省略すると既定の運用（1コマ2台・1回1台・住民の画面からの予約は受け付けない・空き状況と電話受付は今日から3か月先まで・コマ開始まで）。項目は下の表 | 任意 |

- パスコードは8文字以上。管理者に**口頭か紙で**伝える（メールで送らない）。
- エディタで `setup_run` を選んで実行する（初回は権限の許可が必要）。
- 実行後、`ADMIN_INVITES` は自動で消える（パスコードの平文を残さない）。保存されるのは塩付きハッシュだけ。
- 通知処理のトリガー（毎日1回、`RULES.remindHour` の時（既定は17時）の `job_processNotifications`）と、保管のトリガー（毎日夜中の `job_archiveLedger`）も自動で作られる。「トリガー」画面で確認する。
- 通知処理は、メールのある確定の予約に、利用日の前日に「明日のご予約」の案内を1通送る。受付のときにはメールを送らない（結果は、申込みの次の画面で見せる。D-030）。
- `remindHour` を変えたときと、前の版（5分ごとの通知のトリガー）から入れ替えたときは、`setup_run` をもう一度実行する。古い通知のトリガーは消え、1日1回のものに作り直される。

管理者を追加・パスコードを変更するときは、`ADMIN_INVITES` に同じ形式で入れて、もう一度 `setup_run` を実行する（既存の管理者は残る）。
管理者を外すときは、スクリプトプロパティ `ADMINS`（JSON）から該当のメールアドレスの項目を削除する。

## 4. ウェブアプリとして公開する

1. 「デプロイ > 新しいデプロイ > 種類：ウェブアプリ」
2. 次のユーザーとして実行：**自分**、アクセスできるユーザー：**全員**
   - 住民は Google ログインなしで使える（仮の決定 D-002）
   - 管理者の確認は Google アカウントではなく、管理者パスコードで行う（D-001）
3. 表示された URL が利用者用。管理者用はその末尾に `?page=admin` を付ける。
4. 住民への案内には利用者用 URL だけを載せる（管理者用 URL を知っていても、パスコードが無ければ何もできない）。
5. **公開の URL は、デプロイ（公開の単位）ごとに決まる。** 「新しいデプロイ」を作るたびに、別の URL になる。本番では、デプロイは1つだけ作り、以後は手順5の「既存のデプロイを編集」だけで更新する。
   - 「デプロイを管理」で表示されるデプロイ ID を、`docs/` 以外の安全な場所（管理組合の控え）に書いておく。
   - 末尾が `/dev` の URL（テスト用）は、編集できる人しか開けない。住民に配らない。
6. **QRコードには、GAS の URL を直接入れない方がよい。** 管理組合が自分で中身を変えられるページ（管理組合のホームページの1ページなど）の URL を QR にし、そこから GAS の URL へ案内する。万一 GAS の URL が変わっても、そのページの案内先を直すだけで、QRコードは刷り直さずに済む（検討資料 7章）。
7. **住民の画面と管理者の画面は、GAS の外（Cloudflare Pages など）に置く**（D-034・D-035）。手順は `docs/STATIC_PAGES.md`。QR には、そのページの URL を入れる。

## 5. 更新するとき

URL は変わらない。前の版にもすぐ戻せる。

1. 検証用の環境で、ハーネス（`npm run verify:strict`）に合格した版を反映して確かめる。
2. 本番の台帳を複製しておく（「ファイル > コピーを作成」）。
3. 本番の GAS プロジェクトに反映する。
4. 「デプロイを管理」で**既存のデプロイを編集**し、バージョンを「新バージョン」にする（URL を変えないため）。**「新しいデプロイ」は押さない。**
5. `Config.gs` の `APP_VERSION` を更新しておくと、どの版が動いているか分かる。

前の版に戻すとき：「デプロイを管理」→ 既存のデプロイを編集 → バージョンで、前の番号を選ぶ。URL は変わらない。台帳（スプレッドシート）は戻らないので、シートの形を変えた版のときは、手順2の複製と合わせて考える。

clasp を使うとき（clasp 3.4 で確かめた）：
- `clasp push` で本番の GAS プロジェクトにファイルを送る。
- `clasp create-version "0.2.1"` で版を作る。
- `clasp update-deployment <デプロイID> -V <版の番号>`（`clasp redeploy` でも同じ）で、**既存のデプロイ**を新しい版にする。
- **`clasp deploy`（`create-deployment`）を `-i <デプロイID>` 無しで実行すると、新しいデプロイ（新しい URL）ができる。** 本番では使わない。
- 戻すときは `clasp update-deployment <デプロイID> -V <前の版の番号>`。

## 6. バックアップと担当者交代

- バックアップ：台帳スプレッドシートを「ファイル > コピーを作成」で定期的に複製する（週1回程度）。
- 担当者交代：**持ち主（オーナー）を替えずに済むよう、最初から管理組合用の Google アカウントで作り、担当者が替わったら、そのアカウントのパスワードと2段階認証を引き継ぐ。** 個人のアカウントで作った場合は、持ち主を移すとトリガーが止まり、公開の手順もやり直しになり、URL が変わることがある（本物の GAS で確かめる：REAL_ENV_CHECKLIST 2章）。

## 7. 困ったとき

| 症状 | 確認すること |
|---|---|
| 画面に「空き状況を表示できませんでした」 | `SPREADSHEET_ID` が正しいか。スプレッドシートを削除・移動していないか |
| メールが届かない | 管理者画面「電話連絡が必要な予約」に出ていれば、送信に失敗している（再送待ち）。1日の送信上限（無料アカウントは100通）に達していないか |
| 管理者の確認ができない | パスコードを5回間違えると15分止まる。時間をおくか、`ADMIN_INVITES` で再設定 |
| 台帳を直接直したい | 原則として画面から操作する。やむを得ず直す場合は「予約」と「割当て」の両方を同じように直し、「操作履歴」に理由を書く |

## 付録：設定 `RULES` の項目（2026-11-07 時点）

`RULES` を書くときは、変えたい項目だけを JSON で書けばよい（書かない項目は既定の値）。例：`{"capacityPerSlot": 3}`

| 項目 | 既定の値 | 意味 |
|---|---|---|
| `capacityPerSlot` | 2 | 1コマに入れる台数。区画（91・92・93）は3つあるが、2台で運用する |
| `maxQuantityPerRequest` | 1 | 1回の予約で使える台数 |
| `residentBooking` | false | 住民が画面から予約できるか。`true` にすると、住民の画面の時間帯が押せるようになり、申込みの画面が出る |
| `viewMonths` | 3 | 管理者が電話・窓口で受け付ける範囲（今日から何か月先まで）。管理者の画面はこの範囲を出す |
| `residentLeadDays` | 5 | 住民の画面に見せるのは、今日から何日後からか。それより前の日は見せず、住民の申込みも受け付けない |
| `residentViewMonths` | 2 | 住民の画面に見せるのは、今日から何か月先までか。住民の申込みも、ここまで |
| `remindHour` | 17 | 利用日の前日の、何時（日本時間、0〜23）に「明日のご予約」のメールを送るか。この時刻より後に受けた翌日の予約と、当日の予約には送らない。変えたら `setup_run` を実行し直す（D-030） |
| `archiveAfterDays` | 60 | 利用日がこの日数より前の予約を、毎日夜中に「予約（保管）」などのシートへ移す。保管した日付には、管理者も登録・取消しができない（D-023） |
| `residentLookup` | false | 住民が予約番号と電話番号の下4けたで自分の予約を確かめる入口。画面からは外しているので閉じておく。本物の GAS での試験で使うときだけ `true` にする |
| `bookingWindowDays` | （なし） | 住民の申込みを、さらに「今日から何日先まで」に絞るとき（数で書く）。書かなければ、住民の画面に見せる範囲と同じ |
| `cutoff` | `SLOT_START` | コマの開始時刻を過ぎたら受け付けない |

## 付録：2026-11-07 の更新（使用禁止）を、すでに動いている GAS に入れるとき

1. GAS プロジェクトに `src/` の全ファイルを入れ直す（新しいファイル `Block.gs` を含む）。
2. GAS のエディタで `setup_run` を実行する。台帳のスプレッドシートに「使用禁止」シートが足される（ほかのシートの中身は変わらない）。
3. デプロイを更新する（「デプロイを管理」→ 編集 → 新しいバージョン）。

## 付録：2026-11-07 の更新（予約表）を、すでに動いている GAS に入れるとき

1. GAS プロジェクトに新しいファイル `Sheet.gs` を足し、ほかの `src/` のファイルも入れ直す。
2. デプロイを更新する（「デプロイを管理」→ 編集 → 新しいバージョン）。`setup_run` を実行し直す必要は無い。
3. 管理者の画面で「予約表」→「スプレッドシートに書き出す」を押すと、台帳のスプレッドシートに「予約表 2026年11月」のようなシートができる。以後は、管理者が登録・取消し・使用禁止をするたびに自動で作り直される。
4. Excel が要るときは、そのスプレッドシートを開き、「ファイル → ダウンロード → Microsoft Excel (.xlsx)」を選ぶ。予約表のシートは作り直すたびに上書きされるので、書き込みは台帳ではなく、ダウンロードした Excel の方で行う。

## 付録：版 0.2.0（2026-11-07）を本番に入れる手順（まとめ）

上の2つの付録（使用禁止・予約表）を、本番に入れる順にまとめたもの。

1. **台帳を複製しておく**：本番の台帳スプレッドシートで「ファイル > コピーを作成」。名前の例：`駐車場予約 台帳（本番）0.2.0 の前`。
2. **スクリプト プロパティの `RULES` を確かめる**（本番の GAS プロジェクト > プロジェクトの設定）。
   - 0.2.0 では、書かない項目は「1コマ2台・1回1台・住民の画面からの予約は受け付けない・3か月先まで」になる。
   - 前の版のときに `RULES` を書いていて、`maxQuantityPerRequest` や `capacityPerSlot` が入っていれば、それが優先される。今の運用に合わなければ、その項目を消すか、`RULES` ごと消す。
3. **ファイルを入れ替える**：`src/` の全ファイル（`.gs` 10個、`.html` 4つ、`appsscript.json`）。新しいファイルは `Block.gs`・`Sheet.gs`・`Archive.gs`。
4. **`setup_run` を1回実行する**：「使用禁止」と保管用の3つのシート、保管のトリガーが足される。ほかのシートの中身と管理者の登録はそのまま。
5. **デプロイを更新する**：「デプロイを管理」→ 既存のデプロイを編集 → バージョン「新バージョン」。URL は変わらない。
6. **確かめる**：
   - 住民の画面が縦の一覧になり、○×と A〜D が出る。右上で「カレンダー」に切り替えられる。予約の申込みの画面と「予約の確認」は出ない。
   - 「トリガー」画面に `job_processNotifications`（日タイマー、`remindHour` の時）と `job_archiveLedger` がある。`job_processNotifications` が5分ごとのまま残っていれば、`setup_run` をもう一度実行する（D-030）。
   - 管理者の画面の「予約表」→「スプレッドシートに書き出す」で、台帳に「予約表 2026年11月」のシートができる。
   - 試しに未来の日を1コマ使用禁止にして、住民の画面で×になることを見てから、解除する。
