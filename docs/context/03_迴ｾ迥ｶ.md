## 3. 手元（ローカル）での動かし方

GAS に移す前に、PC の上で画面を触って確かめられる。必要なのは Node.js 20 以上だけ。

```
cd parking-gas
npm run serve
```

起動すると、次の入口が表示される。

| 入口 | URL（既定） | 備考 |
|---|---|---|
| 利用者画面 | http://127.0.0.1:8787/exec | |
| 管理者画面（確認なし） | http://127.0.0.1:8787/__harness/admin-auto | 手元確認用。管理者の確認を自動で済ませる |
| 管理者画面（本番と同じ） | http://127.0.0.1:8787/exec?page=admin | メール `kanri1@example.org`、パスコード `kanri-test-1234` |
| 台帳の中身・送ったメール | http://127.0.0.1:8787/__harness/ledger | スプレッドシート相当の4シートを表で見る。通知の送信も1回分実行できる |

- 画面の「今日」は 2026年10月19日9時（仮想の時刻）。いくつかの予約が入った状態で始まる。
- データはメモリ上にあり、止めると消える。
- `__harness/` で始まる入口は手元確認用の起動にだけあり、GAS には含まれない。

自動試験も手元で回す場合：
```
npm i -D playwright
npx playwright install chromium
npm run verify
```

## 5. 既知の問題と弱点

| 問題 | 影響 | 対応案 |
|---|---|---|
| 本物の GAS で未確認 | エミュレータの仮定（約30項目、多くは未確認）が外れていると本番で動かない | 実環境プローブ（`harness/real-gas/`）を最初に実行する |
| 通勤中の親のペルソナは手数に余裕が少ない（12手中10手） | 入力欄の数が手数の大半 | 2回目からは前回の入力が残る。棟と部屋の入力の工夫など |
| 利用者の最初の画面は今日からの7日分 | 翌週の予約は「次の週」を1回押す | 2週分を並べるか、人の確認で判断 |
| 画面の自動監査は、管理者画面を確認前でしか測らない | 確認後の画面の崩れを見逃しうる（r8 で実際に発生） | 画面試験 UI-07 で補っている。監査の拡張は人の判断待ち |
| 「棟」の書き方（B か B棟か）が分からないという指摘が複数 | 入力の揺れ | 棟を選択式にする（棟の一覧が分かれば） |
| 受付中のまま放置された予約は、再送されないと枠が残る | まれに枠がふさがる | 一定時間たった受付中を片付けるトリガーを足す |
| 通知処理が送信中に止まると、同じメールが2通届くことがある | まれな重複通知 | 許容（届かないよりよい） |
| パスコードを忘れたら運用担当者が再設定するしかない | 運用の手間 | 手順は `docs/SETUP.md` |
