### 2.3 本番の公開（試験で問題が無かったら）

`docs/SETUP.md` の手順で行う。要点：

1. **管理組合用の Google アカウントで作る**（持ち主を後で替えると、トリガーが止まり、URL が変わることがある）。
2. **予約の入っていない新しいスプレッドシート**を作り、`setup_run` で初期化する。試験の台帳は使わない。試験用の `TestSeed.gs` は貼らない。
3. スクリプト プロパティを設定する。
   - `RULES`：本番の既定のまま。`residentBooking:false`、`residentLookup:false`。
   - `ADMIN_INVITES`：管理者のメール・氏名・パスコード。
   - `CONTACT_NOTE`：例 `理事会事務局（電話 0X-XXXX-XXXX）`。番号を入れると、電話のボタンになる。
   - `RECEPTION_HOURS`：省略すると「受付時間　AM 10:00〜12:00　PM 14:00〜19:00」。
   - `TERMS`：利用約款の本文。**本文はまだ依頼者から受け取っていない。** 空なら「利用約款」は出ない。
4. **デプロイは1回だけ作る。** 以後は「デプロイを管理 → 既存のデプロイを編集 → 新しいバージョン」だけで更新する（URL が変わらない）。
   - デプロイ ID を管理組合の控えに残す。
   - 「新しいデプロイ」や、`-i` 無しの `clasp deploy` は使わない（URL が変わる）。
5. **住民の画面と管理者の画面は GAS の外（Cloudflare Pages）に置き、QR にはその URL を入れる**（D-034・D-035、`docs/STATIC_PAGES.md`、ゴールは `docs/GOAL-外の画面.md`）。GAS の画面は、複数の Google アカウントにログインした端末で「ファイルを開くことができません」になるため。外のページからの `doPost` の呼び出しは、本物の GAS でまだ確かめていない。
6. clasp の操作と Google への送信は、依頼者がはっきり頼んだときだけ行う。ログインと資格情報は、依頼者が自分で行う。

### 2.4 住民の予約を本番で開く前に決めること（急ぎではない）

- **なりすまし・枠の占拠**
  - 名前・部屋・メールは、誰でも名乗れる。
  - **依頼者が断った方法**：部屋ごとの合言葉、Google ログイン、メールの確認リンク。この3つは提案しない。
  - 監督が出した案：
    - Web 予約の受付数に、全体の上限（1時間・1日あたり）を設ける。
    - Web から入った予約を、管理者の一覧で分かるようにする。
    - 仮の予約にして、事務員が電話で確かめる。
  - 依頼者の返事待ち。
  - メールの踏み台の問題は、前日の送信（D-030）で、1日の数がその日の予約の数までに収まった。
- **1人あたりの上限（依頼者の決定）**
  - 1回の申込みで1枠。
  - 同じ部屋の連続は、区画が違っても4枠まで（例：B・C・D と翌日の A）。
  - 管理者の登録は除く。
  - 本人の確かめが無いので、まだ入れていない。
- **区画を2つ借りたいときの扱い**：未定。
  - コードを直すことになっても、既存のデプロイの更新で済み、URL は変わらない。
  - 住民の予約を開くこと自体も、`RULES` を変えるだけで、URL は変わらない。

## 4. 守ること（依頼者の好みと、このリポジトリの決まり）

- 返事は日本語で、助詞を省かずに書く。
- 画面の分かりにくさを、説明の文で補わない。ボタンや固定の手順（モード）を増やさない。入力を保つなど、流れを柔らかくする方で解く。
- 見た目は、やわらかく、AI が作ったように見えないこと。
- `src/` の文字は Shift_JIS の範囲に収める。
  - ①②③、～（全角チルダ）などは使えない。1. や 〜（波ダッシュ）を使う。
  - 確かめ方：`python -c "import glob;[open(f,encoding='utf-8').read().encode('shift_jis') for f in glob.glob('src/*')]"`
- ペルソナ評価は行わない。
- **封印されたファイル**は勝手に変えない。
  - 対象：`harness/`、`tests/acceptance/`、`tests/helpers.js`、`tests/ui/ui-helpers.js`、`personas/`、`contract/provisional-rules.json`、`contract/ui-tests-required.json`、`contract/perf-budget.json`、`docs/REQUIREMENTS.md`、`docs/requirements-index.json`。
  - 依頼者が仕様を変えたときだけ、依頼者の直接の許しを得て書き換える。差分を見せ、許しを得てから `npm run harness:seal` を行う。
  - 書き換えた後は、`npm run selftest:quick` も流すこと（2026-11-10 に、受入試験 07 を変えたとき、見本の実装と 06 にも響いた）。
- 試験を弱めて合格させない。adapter で結果を書き換えない。
- 何を入れても通る管理者のログインは、手元の確認用（`tools/serve-local.js`）だけ。`src/` の確かめは変えない。
- URL は変えない（QR で配る）。
