# 仕様から作った試験の一覧（テスト担当、2026-11-09）

この一覧は、実装を読む前に、仕様の文書と公開の入口だけから書いた「このシステムがどう動くべきか」である。
試験は `tests/spec/` にあり、試験の名前の先頭に `[S-xxx]` を付けている（一覧の ID と対応する）。

- 実行：`node --test "tests/spec/*.test.js"`
- 前提の設定：**本番の既定**（1コマ2台・1回1台・住民の予約は閉じる・住民に見せるのは今日+5日〜2か月先・管理者は今日〜3か月先・保管は60日・予約の確認は閉じる）。受入試験の前提（`HARNESS_PREMISE`）は使わない。必要な試験だけ、設定 `RULES` で項目を開ける（例：住民の予約を開く）。
- 基準の時刻：2026-11-09（月）9:00（日本時間）。試験ごとに仮想時計を動かす。
- 根拠の略号：REQ＝`docs/REQUIREMENTS.md`、D-xxx＝`docs/DECISIONS.md`、SETUP＝`docs/SETUP.md`、検討＝`docs/検討-2026-11-09-安全と構成.md`、CLAUDE＝`CLAUDE.md` 5章。

## 確かめ方の共通部分

- 台帳の不変条件（二重予約・割当ての残り・受付要求IDの二重）は、毎回、試験の終わりにシートを直接読んで確かめる（`harness/invariants.js`）。
- それに加えて、`tests/spec/spec-env.js` で次を毎回確かめる：1コマの有効な割当てが上限（2台）以下／有効な使用禁止のある区画に、使用禁止の登録より後に入った有効な割当てが無い。
- 同時の処理は、エミュレータの `host.runConcurrently`（全員の読込みがそろってから一斉に走らせる）で起こす。
