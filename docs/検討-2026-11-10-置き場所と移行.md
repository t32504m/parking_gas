# 検討：画面とデータをどこに置くか（2026-11-10）

2026-11-10 の配布は見送った。急ぎで作った D-034（住民の画面を外に置く）を見直し、時間を掛けて決める。

## 1. 前回、何が起きていたか（原因はまだ確定していない）

- 起きたこと：QR から住民の画面を開くと、スマホの**どのブラウザでも、プライベートモードでも**「現在、ファイルを開くことができません」。パソコンのシークレット ウィンドウでは開けた。
- Google の説明では、この文言の主な原因は「1つのブラウザで複数の Google アカウントにログインしている」こと（GAS は複数ログインに対応していない）。
- **ただし、プライベートモードには Google のログインが無い。** だから、プライベートモードでも出たなら、複数ログインだけでは説明できない。
- いちばん疑わしいのは **QR に入れた URL の形**。
  - アドレス欄から写した URL には、`/macros/u/1/s/…/exec` のように、ログインの番号（`/u/1/`）が入ることがある。ログインしていない端末では、その番号のアカウントが無いので開けない。
  - `/dev` で終わる URL は、編集できる人しか開けない。
  - 正しいのは、デプロイの画面の「ウェブアプリ」の欄の `https://script.google.com/macros/s/…/exec`（`/u/数字/` が無い）。
- 実機の記録（`real-test-results/probe/`）では、未ログインのパソコンで、`/exec` の住民の呼び出しが動いている（1回 0.55〜0.85 秒）。

**確かめ方（依頼者、10分）**：QR に入れた URL に `/u/` か `/dev` が入っていたかを見る。次に、デプロイの画面の URL を、スマホのプライベートモードと、ふだんのブラウザ（複数ログイン）で開く。

| 結果 | 分かること |
|---|---|
| プライベートで開ける、ふだんのブラウザで開けない | 原因は2つ（URL の形と複数ログイン）。複数ログインの住民には、外に置く画面が要る |
| どちらでも開ける | 原因は URL の形だけ。外に置く画面は無くてもよい（あっても害は無い） |
| プライベートでも開けない | 別の原因（デプロイの設定・アカウントの種類）。設定の画面を見せてもらう |

## 3. 勧め

1. **まず 1章の確かめ方で、原因を確定する**（作業の前に）。
2. 原因に複数ログインが入っていれば、**A+** にする。
   - 管理者の画面も、住民の画面と同じ作り方（`App.call` を `fetch` に替える）で外に置ける。管理者の画面のサーバーの呼び出しは、`App.call` の1か所に集まっているので、作り直しは小さい。
   - 管理者の確認は、今もメールとパスコード（Google のログインは使っていない、D-001）なので、クッキーを送らなくても変わらない。
   - サーバーの関数とスプレッドシートは変えないので、今の試験がそのまま合否の基準になる。
   - 外のページの URL（`*.pages.dev`）を QR にすれば、GAS の URL が変わっても刷り直さずに済む。
3. **B（Cloudflare へ移す）は、今は勧めない。** 速さと同時の申込みには強いが、スプレッドシートの台帳（事務員が見る・直す）を失い、住民へのメールに外の会社が要り、試験の積み重ねを作り直すことになる。GAS の上限や速さが、実際に問題になってから考える。そのときも、A+ の外の画面はそのまま使える（呼び先を替えるだけ）。
4. **C（Firebase）は勧めない。** 台数の上限を確実に守るには Functions が要り、カードの登録が要る。依頼者の心配（Google にある）も解けない。
