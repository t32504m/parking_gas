# 本物の GAS と Cloudflare Pages での自動試験（他の AI が行うための設計書）

この文書は、**このシステムを本物の環境で自動で試験する AI** のためのものである。
コードを読まなくても試験を組み立てられるように、状況・「本来あるべき状態」・「最悪の場合（それを狙う）」・手順の型・報告の形を書いた。
（2026-11-12 作成。D-001〜D-039 の時点。）

---

## 0. 最初に知ること（5行）

1. 自治会の駐車場の予約を、**Google スプレッドシート（台帳）＋ GAS（処理）＋ Cloudflare Pages（画面）**で管理している。
2. 画面（住民用・管理者用）は Pages に置いた静的な HTML で、データは `fetch` で GAS の `doPost` に頼む。
3. **住民は空き状況（○×）を見るだけ**。予約は電話で受け、**管理者が代行登録**する。住民の申込み・予約の確認の入口は、本番では閉じている（試験のときだけ開ける）。
4. この試験の目的は、エミュレータでは確かめられないこと（本物の Google の遅さ・同時アクセス・ブラウザの違い・CORS・リダイレクト・上限）を、**壊れ方を狙って**確かめること。
5. **あなたは `src/` を直さない。** 見つけたことを報告するのが仕事である（8章）。

## 1. 状況

### 1.1 しくみ

```
住民のスマホ ──┐                                  ┌── スプレッドシート（台帳）
              ├─ Cloudflare Pages（静的 HTML）── fetch(POST, text/plain, credentials:'omit') ──> GAS /exec（doPost）
管理者の PC ───┘     /        住民の画面                 302 → script.googleusercontent.com（ACAO: *）
                     /admin/  管理者の画面
```

- 画面は、開いたときに `config` を1回呼ぶ。住民の画面は、この1回で「設定＋最初の月の空き状況」を受け取る（D-037）。
- `doPost` の本文は `{"fn": "<関数名>", "args": [...]}`。呼べる関数は決まった一覧だけで、ほかは `DENIED` になる（D-035・D-036）。
  - 住民：`config` `api_getAvailability` `api_submitReservation` `api_getRequestStatus` `api_lookupReservation`
  - 管理者：`api_admin_login`、ほか `api_admin_*`（`args[0]` に `{token}`、`args[1]` に中身）
- 管理者の認証は、**メール＋パスコード**で `api_admin_login` を呼び、受け取った `token`（6時間）を以後に付ける。Google のログインは使わない（D-001）。同じメールで15分に5回まちがえると、しばらく止まる。
- GAS の1回の呼び出しは、**1.5〜3秒**かかる（Google 側の固定の時間）。データの量では、ほとんど増えない（台帳は毎晩、60日より前の行を「保管」のシートへ移す。D-023）。
- 管理者の週の表は、開いたときに**今月と来月の2か月分を1回で読み**、その範囲の週の移動では GAS を呼ばない。「次の月」で読んでいない月へ行くときだけ、1か月分を読む（D-038）。
- 電話番号は、保存のときに `090-1234-5678` の形にそろえる（全角・ハイフンなし・空白・長音記号なども受け付ける。D-039）。

### 1.2 試験に使うもの（環境変数で渡す。**ファイルに書かない**）

| 変数 | 中身 | 例 |
|---|---|---|
| `PAGES_URL` | 試験用の Pages の URL | `https://parking-test-7e8.pages.dev` |
| `GAS_URL` | 試験用の GAS の `/exec` の URL | `https://script.google.com/macros/s/AKfycbw-…/exec` |
| `ADMIN1_EMAIL` `ADMIN1_PASS` | 試験用の管理者1 | 依頼者から、実行のときにだけ受け取る |
| `ADMIN2_EMAIL` `ADMIN2_PASS` | 試験用の管理者2（同時の試験に使う。無ければ、その試験は飛ばして報告） | 同上 |
| `ALLOW_RESIDENT_BOOKING` | 依頼者が `RULES.residentBooking` と `residentLookup` を `true` にしたら `1` | `1` か空 |

- **本番の URL には、一度も送らない。** 本番と試験の URL の区別が付かないときは、止まって聞く。
- 試験で作る予約のお名前は、必ず **`自動試験 ` で始める**（片付けで探すため）。電話番号は `090-0000-` で始まる、実在しない形を使う。メールは空にする（本物のメールを送らないため）。

### 1.3 制約（壊さないために）

- 無料の Google アカウントの上限がある（同時に動く処理は約30、1日の処理時間、メールの数）。**1分に60回を超える呼び出しを続けない**。同時の試験でも、同時は10までにする。
- 試験の結果を読むのに、スプレッドシートを直接は開かない（Google のログインが要るため）。**管理者の API（`api_admin_week` `api_admin_list` など）を、答え合わせに使う。** 依頼者がスプレッドシートを目で見る項目は、別に「人が見る」と書く。
- 今日の日付は本物の日本時間である。日付は、`config` の `today` を基準に計算する（PC の時計を使わない）。

### 1.4 道具

- Node.js 20 以上と Playwright（`npx playwright install chromium webkit`）。
- スマホは Playwright の `devices['iPhone 13']`（webkit）と `devices['Pixel 7']`（chromium）で代わりにする。**本物の端末でしか分からないこと（`tel:` のリンク、複数アカウントの Safari）は、「人が見る」とする。**
- 下の型をそのまま使ってよい。

```js
// e2e/lib.js
const GAS = process.env.GAS_URL, PAGES = process.env.PAGES_URL.replace(/\/$/, '');
async function gas(fn, args) {
  const t0 = Date.now();
  const r = await fetch(GAS, { method: 'POST', redirect: 'follow', headers: { 'Content-Type': 'text/plain;charset=utf-8' }, body: JSON.stringify({ fn, args: args || [] }) });
  const text = await r.text();
  let json = null; try { json = JSON.parse(text); } catch (e) {}
  return { http: r.status, ms: Date.now() - t0, json, text };
}
async function login(n = 1) {
  const r = await gas('api_admin_login', [{ email: process.env[`ADMIN${n}_EMAIL`], secret: process.env[`ADMIN${n}_PASS`] }]);
  if (!r.json || r.json.status !== 'OK') throw new Error('管理者に入れない: ' + r.text.slice(0, 200));
  return { token: r.json.token };
}
const rid = (tag) => `e2e-${tag}-${Date.now()}-${Math.random().toString(36).slice(2, 8)}`;
module.exports = { GAS, PAGES, gas, login, rid };
```

- 画面の試験では、**GAS への呼び出しを数えて時間を測る**（`page.on('request')` と `page.on('requestfinished')` で、URL が `script.google.com` か `googleusercontent.com` のもの）。

## 2. 守ること

1. `src/`・`tests/`・`harness/` を直さない。試験は `e2e/`（新しいフォルダ）に書く。
2. 試験を、通るように弱めない。期待と違ったら、それが結果である。
3. 秘密（パスコード・token）を、ログ・スクリーンショット・報告に出さない（`***` にする）。
4. 試験で作ったものは、終わったら片付ける（9章）。片付けられなかったものは、予約番号を報告に書く。
5. 試験の途中で、同じ失敗が3回続いたら止めて報告する（上限に触れている可能性がある）。

## 3. 本来あるべき状態（不変の条件）

どの試験の後でも、次が成り立っていなければならない。**各試験の最後に、確かめられるものは全部確かめる。**

| ID | 本来あるべき状態 | 確かめ方 |
|---|---|---|
| I-1 | 1つのコマで、有効な予約の台数が区画の数を超えない | `api_admin_week` の `avail[日][コマ]` の残りが0以上。予約の数と残りの和が区画の数 |
| I-2 | 同じ受付要求ID を何回送っても、予約は1件だけ | 同じ `requestId` で送り直し、`api_admin_list` の件数が1 |
| I-3 | 住民への応答に、台数・氏名・電話番号・部屋番号が入らない（○×だけ） | `api_getAvailability` と `config` の応答の文字列に、試験で入れた名前・電話・部屋が無い。数の欄が無い |
| I-4 | 管理者の関数は、正しい token が無ければ何も返さず、何も書かない | token 無し・偽・期限切れで呼び、`status` が `OK` でない。台帳が変わらない |
| I-5 | 画面に出る空きと、管理者の API の空きが一致する | 住民の画面の○×と、`api_admin_week` の残りが0か否かが一致 |
| I-6 | 電話番号は、保存の後に `0` で始まる文字列のまま（数・日付にならない） | `api_admin_list` で見る電話番号が、1.1 の形 |
| I-7 | 変更は「新しい枠が取れたら元を放す」。途中で失敗しても、両方を失うことはない | 変更の失敗の後に、元の予約が有効のまま |
| I-8 | `doPost` は、どんな本文にも JSON で答え、500 や HTML のエラー画面を返さない | 壊れた本文を送り、`json` が `null` でない |
| I-9 | 画面は、読み込み中に、押せない部品（空のボタン）を出さない | 読み込みの表示が消えるまで、`main` の中にボタンが見えない |
| I-10 | 住民の画面の最初の表示は、GAS の呼び出し1回で出る | 開いてから○×が出るまでの GAS への POST が1回 |
| I-11 | 管理者の週の表は、読んだ2か月の中では、週を送っても GAS を呼ばない | 「次の週」を4回押す間の POST が0回 |

## 4. 最悪の場合（これを狙って試験する）

「起きたら困ること」から逆に考える。困り方の大きい順に並べた。**各項目は、起こそうとして起こらなかったことを確かめる試験である。**

| ID | 最悪の場合 | どう狙うか | 合格の条件 |
|---|---|---|---|
| W-1 | **二重の予約**（同じ区画に2台。当日に車が入れない） | 残り1台のコマに、別の受付要求IDで10件を同時に送る（管理者の代行登録で。`ALLOW_RESIDENT_BOOKING` なら住民の申込みも混ぜる） | 確定は1件だけ。I-1 |
| W-2 | **管理者2人の画面が古いまま**、同じ枠に登録・変更する | 管理者1と2の画面を開いたまま、1が登録し、2が（読み直さずに）同じ枠を押して登録する | 2は断られ、断った理由が分かる文が出る。表が新しくなる。I-1 |
| W-3 | **送ったのに届いたか分からず、もう一度押して二重** | 「登録する」を連打（20ms 間隔で5回）。通信を遅くして（`page.route` で 8 秒止める）押した後に再読込み | 予約は1件。I-2 |
| W-4 | **画面が出ない**（住民が「壊れている」と思って電話が殺到） | 冷えた GAS（30分以上呼んでいない後）で最初に開く。遅い回線（Playwright の `route` で 3G 相当に遅らせる）。iPhone（webkit）と Android（chromium）。`credentials:'omit'` でない普通の `fetch` でも試す | 15秒以内に○×が出る。出ないときは「もう一度読み込む」の画面になり、白いままにならない |
| W-5 | **他人の名前・電話が住民に見える** | 住民の全関数を、管理者が登録した後に呼び、応答を文字列として検索する。`fn` に `api_admin_week` などを入れ、`args[0]` を省く・`{}`・`{token:''}` | I-3・I-4 |
| W-6 | **管理者になりすまされる** | 総当たり（同じメールに5回まちがえ、その後に正しいパスコード）。token を1文字変える。token を別の管理者のものと入れ替える。`fn` を `setup_run` `job_archiveLedger` `doGet` `include_` などにする | 5回まちがえた後は、正しくても止まる（15分）。それ以外は全部 `DENIED` か認証の失敗。**試験の後に管理者が入れなくなるので、ロックの試験は最後に、ADMIN2 で行う** |
| W-7 | **月の境で表がずれる**（11/30〜12/6 の週で、12月の予約が11月の表に出る、など） | 月をまたぐ週・年をまたぐ週（12/28〜1/3）に予約を入れ、管理者の週の表と住民の一覧の両方で、日付と表の位置を見る | 予約は正しい日の行にある。月ごとに表が分かれ、見出しが「11月」「12月」（D-038） |
| W-8 | **先読みの後に、別の管理者の登録が見えない** | 管理者1が週の表を開いたまま、管理者2が登録する。管理者1が「次の週」で戻ってくる／タブを1分以上裏に置いて戻す | タブを戻したら読み直して見える（1分以上裏にあったとき）。見えないまま登録しようとしたら、W-2 と同じに断られる |
| W-9 | **電話番号が壊れて保存される**（先頭の0が消える、日付になる） | 表の入力を、管理者の画面から入れる：`09012345678` `０９０－１２３４－５６７８` `090ー1234ー5678` `03(1234)5678` `0120-123-456` `+81 90 1234 5678` `1-2-3`（数に見える）`2026/11/12`（日付に見える） | 1.1 の形でそろう。数・日付に見えるものは断られるか、文字列のまま |
| W-10 | **1日の上限に触れて、夕方から誰も使えない** | （しない。上限は測るだけ）試験の全体で、GAS を何回呼んだかを数えて報告する | 回数と、1回の平均・最大の時間 |
| W-11 | **token の期限切れで、入力した内容が消える** | `sessionStorage` の `adminToken` を壊してから「登録する」を押す | ログインに戻っても、入力した内容が残っているか、少なくとも予約は作られず、作られたかどうかが分かる |
| W-12 | **保管（夜の処理）の後に、予約が消える・二重になる** | 2日にまたがる試験：1日目に予約を入れ、翌朝に `api_admin_week` で同じ予約があることを見る | 60日以内の予約は消えない。件数が変わらない |
| W-13 | **巨大な本文・壊れた本文で GAS が止まる** | 本文：空、`null`、`[]`、`{"fn":1}`、200,000 文字、`{"fn":"config","args":"x"}`、Shift_JIS のバイト列 | I-8。直後に `config` が普通に答える |
| W-14 | **古い画面（キャッシュ）が残り、新しい GAS と合わない** | Pages を更新した後、更新前に開いていたタブで操作する | 動くか、「もう一度読み込む」になる。黙って間違った結果を出さない |

## 5. 試験の一覧（この順に行う）

優先度：**A** は毎回、**B** は変更があったとき、**C** は人と一緒に行うとき。

| ID | 優先 | 名前 | 狙う最悪 | 手順の要点 |
|---|---|---|---|---|
| E-01 | A | 住民の画面が開く（iPhone・Android・PC） | W-4 | `PAGES_URL` を開き、○×が出るまでの時間と POST の数を測る。I-9・I-10 |
| E-02 | A | 住民の画面の中身と、管理者の API の答えが一致 | W-5 | E-01 の○×と、`api_admin_week` の残りを、表示している全日・全コマで比べる。I-3・I-5 |
| E-03 | A | 管理者の入口 | W-6 | `/admin/` でログイン。まちがったパスコード1回では入れず、文が出る。正しいもので入れる |
| E-04 | A | 代行登録・変更・取消し（画面で） | W-3・W-9 | 管理者の画面で、空きを押して登録→変更→取消し。各操作の後に API で答え合わせ。I-6・I-7 |
| E-05 | A | 週の表の先読み・月の分け方・「次の月」 | W-7 | 開いたときの POST が1回、「次の週」×4 で0回、月をまたぐ週で表が2つ、「次の月」を2回押すと1回だけ読む（D-038） |
| E-06 | A | `doPost` の守り | W-5・W-6・W-13 | 1.1 の一覧に無い `fn`、token 無し、壊れた本文（W-13 の表）。全部 JSON で断られる |
| E-07 | B | 同時の登録（残り1台に10件） | W-1 | `Promise.all` で `api_admin_register` を10件（それぞれ別の `requestId`）。確定は1件。3回くり返す |
| E-08 | B | 同じ受付要求IDの送り直し | W-3 | 同じ `requestId` で5件を同時に、さらに5秒後に1件。予約は1件、全部の応答が同じ予約番号 |
| E-09 | B | 管理者2人の古い画面 | W-2・W-8 | ブラウザの文脈を2つ。4章の W-2・W-8 の手順 |
| E-10 | B | 電話番号の形 | W-9 | 4章 W-9 の入力を、画面から1つずつ登録し、API で見る |
| E-11 | B | 遅い回線・失敗した通信 | W-4・W-11 | `page.route` で GAS への POST を (a) 8秒遅らせる (b) 1回だけ失敗させる (c) 応答を壊す。画面が白くならず、もう一度できる |
| E-12 | B | 時間の実測 | W-10 | 各関数を10回ずつ呼び、中央値・最大を表にする。冷えた後の最初の1回は別に書く |
| E-13 | C | 住民の申込み（`ALLOW_RESIDENT_BOOKING=1` のときだけ） | W-1・W-3 | 住民の画面から申し込み、管理者の画面に出る。予約番号で確かめる。同時の申込みを E-07 と同じに |
| E-14 | C | 2日目（夜の処理の後） | W-12 | E-04 などで作った予約が、翌朝も同じにある |
| E-15 | C | 総当たりのロック（最後に。ADMIN2 で） | W-6 | 5回まちがえ、6回目に正しいパスコードでも入れない。15分後に入れる |
| E-16 | C | 人が見る | — | `tel:` のリンクで電話がかかる。複数アカウントの Safari で開く。字形。スプレッドシートの見た目 |

### 5.1 書き方の例（E-07）

```js
// e2e/e07-concurrent.test.js
const test = require('node:test'); const assert = require('node:assert/strict');
const { gas, login, rid } = require('./lib');
test('E-07 残り1台に10件を同時に送っても、確定は1件', async () => {
  const auth = await login(1);
  const cfg = (await gas('config')).json;
  const date = addDays(cfg.today, 10); const slotId = 'S1';            // 10日後の朝。空いているかを先に見る
  const before = (await gas('api_admin_week', [auth, { from: date, to: date }])).json;
  // 残りが1になるまで埋める（作った予約番号は片付けのために控える）
  // …
  const reqs = Array.from({ length: 10 }, (_, i) => gas('api_admin_register', [auth, {
    requestId: rid('e07'), date, slotId, quantity: 1, channel: 'PHONE',
    name: `自動試験 同時${i}`, building: '', room: String(900 + i), phone: `090-0000-${String(i).padStart(4, '0')}` }]));
  const res = await Promise.all(reqs);
  const ok = res.filter((r) => r.json && r.json.status === 'CONFIRMED');
  assert.equal(ok.length, 1, '確定が1件でない: ' + res.map((r) => r.json && r.json.status).join(','));
  // I-1：残りが0、予約は増えて1件
});
```

### 5.2 画面の試験の例（E-05）

```js
const { chromium } = require('playwright');
const posts = []; page.on('request', (r) => { if (r.method() === 'POST' && /script\.google/.test(r.url())) posts.push(JSON.parse(r.postData()).fn); });
await page.goto(PAGES + '/admin/');
await page.fill('#lg-email', process.env.ADMIN1_EMAIL); await page.fill('#lg-pass', process.env.ADMIN1_PASS); await page.click('#lg-go');
await page.waitForSelector('#board table.sheet');

for (let i = 0; i < 4; i++) await page.click('#next');

```

## 6. 試験の試験（その試験が、本当に壊れ方を見つけられるか）

本物の GAS のコードは変えられない。そのため、次の2つで「試験が甘くないか」を確かめる。

1. **負の対照を必ず入れる。** 合格の条件を確かめる前に、「同じ確かめ方で、わざと違う答えを見せたら落ちる」ことを1回見る。
   - 例：E-07 では、確定の数を数える関数に、確定が2件の偽の応答を渡すと落ちることを、`e2e/selfcheck.test.js` で確かめる。
   - 例：E-02 では、比べる関数に1か所だけ違う○×を渡すと落ちること。
2. **手元のエミュレータで、壊した版を流す。** このリポジトリの `tools/serve-static.js` は、本物と同じ画面を手元で出す（`node tools/serve-static.js` → `http://localhost:8790`）。`failNext()` で次の呼び出しを失敗させられる。`PAGES_URL=http://localhost:8790 GAS_URL=http://localhost:8790/gas` にして、E-01〜E-06・E-11 を流し、全部通ることを先に確かめる。次に、手元の `src/` の写しの一か所を壊して（例：`formatPhone_` で何もしない、ロックを外す）、該当の試験が落ちることを見る。**壊した写しは試験の後に消し、`src/` 本体を変えたままにしない。**
