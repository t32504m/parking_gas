# UI・UX の見直し（2026年10月19日）

利用者から「UI と UX が悪い。管理者画面は一覧性が悪く、直観的でなく、分かりにくい」との指摘を受けて、画面を洗い出し、仮説を立てて作り直した記録。

## 0. なぜ、これまでの評価で見逃したか

| 原因 | 内容 |
|---|---|
| スマホ幅でしか評価していなかった | 画面監査もペルソナ評価も iPhone SE・Pixel 7 だけ。管理者が PC で使う場面を一度も見ていなかった |
| 「課題を達成できたか」しか測っていなかった | ペルソナ評価の課題はすべて「1件予約する／1件取り消す」。全体を見渡す（いつ・どこが・誰で埋まっているか）課題が無かった |
| 部品の大きさ・文字の大きさは測ったが、情報の密度は測っていなかった | 押しやすさを優先して大きな部品を縦に積んだ結果、1画面に入る情報が極端に少なくなった |
| 評価役は「その手順」の中で判断する | 画面の作り（メニューから入って条件を入れて探す）を前提に、その中で迷わなければ合格と答える。別の作り方の方がよいかは問わない |

→ ハーネス側も直す（4章）。

## 1. 問題の洗い出し

### 管理者画面

| # | 問題 | 根拠 |
|---|---|---|
| A1 | **予約の全体像が見えない**。いつ・どの駐車場が・誰で埋まっているかを一目で見る画面が無い | 予約を見るには「メニュー→予約を探す→条件→探す→縦に並ぶカード」を経る。PC幅でも条件の入力欄だけで1画面が埋まる |
| A2 | **メニュー起点の画面遷移**で、今の状況が隠れる | ログイン後に最初に見えるのは4つの大きなボタンだけ。予約の状況は何も見えない |
| A3 | **登録が「日付を選ぶ」から始まる** | 管理者は「空いている所に入れる」と考えるが、画面は利用者と同じ手順（カレンダー→時間帯→入力）を踏ませる |
| A4 | **PC の画面幅を使っていない** | 最大幅40remの1列。PC では左右が空白 |
| A5 | **1件の情報がカードで縦に長い** | 1件あたり約250px。3件で1画面を超える |
| A6 | **電話連絡待ちが別ページ** | 対応が必要な件数がメイン画面で分からない |
| A7 | **取消しの対象を探す負担** | 予約を探すために、日付の選択肢を開いて選び直す必要がある |

### 利用者画面

| # | 問題 | 根拠 |
|---|---|---|
| U1 | **空き状況が記号だけで、何が空いているか分からない** | カレンダーは ○△× のみ。時間帯ごとの空きは日を押すまで分からない。ペルソナからも「△の意味が分かりにくい」「日を押すまで分からない」 |
| U2 | **日付と時間帯の選択が2段階** | 日を押す→下にスクロール→時間帯を押す |
| U3 | **料金と時間帯の説明が、時間帯ごとに繰り返される** | 4枚のカードに同じ形式の情報が並び、比べにくい |
| U4 | **PC で1列・左右が空白**（A4 と同じ） | |
| U5 | **台数の選択が目立たず、既定の1台のまま進みやすい** | ペルソナ（通勤中の親）の指摘 |
| U6 | **入力欄が多く、手数が上限ぎりぎり** | 通勤中の親 12手中10〜11手 |

## 2. 仮説

| # | 仮説 | 予想される効果 | 確かめ方 |
|---|---|---|---|
| H1 | 管理者の頭の中にあるのは「予約表（台帳）」。**日付×時間帯×駐車場の表**を最初の画面にすれば、全体像が一目で分かる | 状況把握が1画面・0手で済む | PC で1週間分が1画面に入るか。「空いている枠を探す」課題の手数 |
| H2 | **表の空き枠を押すと登録、名前を押すと詳細・取消し**（その場で操作）にすれば、メニューや検索が要らない | 登録・取消しの手数が減る。迷いが減る | 代行登録・取消しの手数（4回目は13手・10手） |
| H3 | 画面を切り替えず、**横（スマホでは下から）に出る作業用の枠**で登録・取消しをすれば、表の文脈を失わない | 終わった後に表へ反映されたことが見える | 取消し後に表の枠が空きに戻るのを評価役が確認できるか |
| H4 | 対応が必要な件数（電話連絡待ち）を**常に見える位置に数字で**出せば、見落としが減る | 別ページを開かなくてよい | |
| H5 | 利用者も「いつ空いているか」を知りたい。**日付×時間帯の空き台数の表**にすれば、記号の意味を覚えなくてよく、**1回押すだけで日と時間帯を選べる** | 手数が減る（日→スクロール→時間帯 が 1手に） | 通勤中の親の手数（10〜11手） |
| H6 | 料金と時間帯は**表の見出しに1回だけ**書けば、比べやすい | 読む量が減る | |
| H7 | PC では**2列**（左に表、右に入力）にすれば、選んだ枠を見ながら入力できる | | PC での画面監査 |
| H8 | 台数は**入力の最初に大きく**出し、「何台ですか」と問いかける | 台数の押し忘れが減る | |

## 3. 改善の内容

### 管理者画面（作り直し）

- 確認後の最初の画面を**予約表**にする。
  - PC：行＝日付（1週間）、列＝時間帯×駐車場（朝91・92・93、昼…、夜…の12列）。各枠に予約者の名字、空きは「＋」、受付時間を過ぎた枠は「－」。
  - スマホ：日ごとに、時間帯の行と駐車場3つの枠を並べる。
- 枠を押すと、PC では右側、スマホでは画面全体に**作業用の枠**が出る。
  - 空き枠：日付・時間帯が入った状態の登録フォーム → 確認 → 登録 → 予約番号と読み上げ文。
  - 予約枠：予約の詳細（氏名・部屋・電話・台数・駐車場・受付・予約番号）と、理由を選んでの取消し。
  - 閉じると、表が最新の状態に更新される。
- 上部の操作列：前の週・今日・次の週、名前・部屋・予約番号での検索（一覧表で表示）、電話連絡待ちの件数（押すと一覧）、印刷。
- メニュー画面と「予約を探す」の条件入力画面はなくした。

### 利用者画面（作り直し）

- 最初の画面を**空き状況の表**（行＝日付、列＝朝・昼・午後・夜）にする。
  - 各枠に「空き3」「残り1」「満車」「－」を文字で出す。
  - 見出しに時間と料金を1回だけ書く。
  - 1週間ずつ前後に移動する。
- 空き枠を押すと、PC では右、スマホでは表の下に、**選んだ枠と入力フォーム**が出る。
  - 台数は「何台ですか」として最初に出す。
- 確認画面・結果画面・通信断の扱い・予約番号での確認は、これまでどおり。

## 4. ハーネスの見直し（評価の穴をふさぐ）

| 変更 | 理由 |
|---|---|
| 画面の自動監査に PC 幅（1280×800）を加える | PC で使う場面を見ていなかった |
| PC で使う管理者のペルソナと、「全体を見渡す」課題を加える | 一覧性・全体把握を評価していなかった |
| ペルソナ評価の主観評価に「一覧性（全体が見渡せるか）」の点数を加える | 達成できたかだけでなく、分かりやすさを測る |

これらは合格基準に関わる変更のため、利用者の指摘（人の判断）に基づくものとして `docs/DECISIONS.md` に記録する。

## 5. 評価 r5 で分かったこと（汚染あり・手がかりとしてだけ使用）

r5 は、評価役どうしのセッション取り違え（HX-006）で操作記録が混ざったため、合否には使っていない。ただし、評価役が挙げた困りごとは画面の問題として妥当なので、次のように直した。

| 困りごと（評価役） | 根本の理由 | 直したこと |
|---|---|---|
| 満車を見て「どうすればよいか分からない」。自治会長に電話しようと思った（高齢の住民） | 満車の枠は押しても何も起きない。行き止まりになっていた | 満車の枠も押せるようにし、押すと**近くの空いている枠**（同じ日のほかの時間帯、次の日以降の同じ時間帯）が、そのまま選べるボタンで出る。説明文は足していない |
| 予約番号が画面の下にあり、スクロールしないと見えない（住民3人） | スマホでは入力と結果が表の下に続いていた | スマホでは、枠を選ぶと**入力と結果が画面全体に出る**（管理者画面と同じ）。予約番号は常に画面の上の方に出る |
| 登録すると「電話連絡」の数字が増え、不完全なのかと不安になる（管理者2人） | 電話で受けて、その場で伝えた予約まで「連絡待ち」に数えていた | メールの無い予約の登録後に「本人に伝えた」を置いた。押すと連絡済みになり、数字は増えない。あとで伝える場合だけ「閉じる」 |
| 取消し後に、選んだ理由が出ず、残せたか分からない（電話番の管理者） | 結果の画面に理由を出していなかった | 「取り消しました」の下に、取り消した理由を出す |
| スマホで25日の枠にたどり着くまでが大変（電話番の管理者） | 7日分の表が縦に長く並んでいた | スマホでは**日付のボタン**（日付・曜日・空きの数）を並べ、押した日だけを表で出す |
| 管理者のスマホで、操作列が画面の大半を占め、表が見えない（r7） | 週の移動・検索・電話連絡・印刷が全て上に並んでいた | 上には週の移動と電話連絡だけ。検索と「今週」は表の下へ |
| 区画の「91・92・93」が何の番号か分からない（管理者2人） | 数字だけの札だった | 札を「91番」にした |
| 選んだボタンが分かりにくい（電話番の管理者） | 色が変わるだけだった | 選んだボタンに ✓ を付けた |

## 6. 仮説の検証（ペルソナ評価 r9、全員合格）

| ペルソナ | 課題 | 達成 | 満足 | 確信 | 見通し |
|---|---|---|---|---|---|
| 78歳の住民（iPhone SE） | 夜の予約 | 達成 | 4 | 4 | 4 |
| 78歳の住民（iPhone SE） | 満車の日 | 達成 | 4 | 4 | 4 |
| 通勤中の親（Pixel 7） | 2台の予約 | 達成 | 4 | 5 | 4 |
| 電波の弱い住民 | 通信断を挟んだ予約 | 達成 | 4 | 5 | 4 |
| 色覚の特性がある住民 | 空きの確認と予約 | 達成 | 5 | 5 | 5 |
| 電話番の管理者（iPhone SE） | 電話の代行登録 | 達成 | 4 | 5 | 4 |
| 電話番の管理者（iPhone SE） | 電話での取消し | 達成 | 5 | 5 | 4 |
| PCの管理者（新規） | 1週間を見渡して登録 | 達成 | 4 | 5 | 5 |

| 仮説 | 結果 |
|---|---|
| H1 予約表を最初の画面に | **支持**。PC の管理者は「ログイン直後の週の表で、夜に予約が入っているのは10/24だけだと説明なしで分かった」（見通し5）。 |
| H2 表の枠を押して登録・取消し | **一部支持**。取消しは 10手（r4）→ 8手（r9）に減り、メニュー画面を経なくなった。代行登録は 13手 → 14手で**減っていない**（手数の大半は確認と入力欄の5項目。スマホでは日付ボタンを押す1手が増えた）。ただし利用者の指摘どおり、問題の中心は手数より分かりにくさで、見通しは全員4以上になった。 |
| H3 作業の枠で文脈を失わない | **条件つきで支持**。PC では表の横に出す形がよく働いた。スマホでは表に重ねると「どこから先が申し込みか分からない」「スクロールが効かない」となり（r6）、**表を隠して枠だけを出し、閉じると表の同じ位置に戻す**形に改めて解消した。 |
| H4 電話連絡の数を常に見せる | **条件つきで支持**。数字が増える理由が分からないと不安を生んだ（r5）。電話口で伝えた予約を数えないようにして解消。 |
| H5 利用者も空き状況の表に | **支持**。色覚の特性がある住民は見通し5。全員が1回押すだけで日と時間帯を選べた。 |
| H6 料金と時間帯は見出しに1回 | **支持**（不満なし）。 |
| H7 PC は2列 | **支持**。 |
| H8 台数を最初に | **一部**。2台の予約で「1台のままで押し忘れそう」との声が続く（minor）。選んだボタンに ✓ を付けたが、根本は残る。 |
| 追加 満車を行き止まりにしない | **支持**。78歳の住民の「満車の日」は満足 2（r5）→ 4（r9）。 |

### 残る小さな指摘（いずれも minor）

- 今日の朝の「－」（受付時間を過ぎた枠）の理由が分からない。
- 通信が切れた画面に「もう一度申し込まなくてよい」の一言が欲しい（ただし、案内どおり「結果を確かめる」で迷わず解決している）。
- 最初の画面が今日からの7日分のため、翌週の予約には「次の週」を1回押す。
- 予約番号の使い道（いつ必要になるか）が分からない。運用ルールが決まってから書く。

これらは文や注釈を足せば点数は上がりうるが、利用者の指示（「文や注釈を入れてほしいわけではない」）に従い、今回は足していない。
