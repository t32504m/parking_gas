## P-1 GAS画面の初回表示を1往復にする（読み込み体感。依頼者の不満に直結）
- 目的: 外の画面（Cloudflare Pages版）は `config` 応答に最初の1か月分を既に埋め込んでいる（src/Web.gs の case 'config'、D-032）。**GAS内の画面（doGetで出す Index.html）だけ、初期表示に api_getAvailability で2往復している**。最初の1か月分を doGet の HTML に埋め込んで、初期表示の待ちを1往減らす
- やり方の手がかり: 静的版の埋め込みと同じ形。`<?= ?>` でJSに埋める値はスクリプトコンテキストのエスケープ前提（PT-F2・D-036の扱いを踏襲。文字列化するなら JSON.stringify→`<`のサニタイズ）。Index.html 側は `S.online` などを埋め込み値から初期化し、埋め込みが無いときは現在どおり api_getAvailability する（外の画面は変更しない）
- 受け入れ: 新しい実装試験（例 `tests/impl/gas-first-month.test.js`）で「doGet の HTML に最初の月の days が含まれる／Index.html は初回の空き読みを埋め込みから始める」。UI試験22と `tests/impl/static-resident.test.js` はそのまま緑
- レッドライン: doGetで失敗しても画面は開けること（埋め込みが失敗したら従来動作へ落ちる）。`<?= ?>` に未エスケープの値を混ぜない（XSS試験PT-F2・PT-D2を緑のまま）
- 規模: 小（Web.gs と Index.html の初期化だけ）

## P-5 満車(FULL)狙いの攻撃がロックを取る問題（**人判断待ち・着手禁止**）
- 現状: 過去日・締切後・期間外・連続超過はロック前に即断するようになった（D-042・G2）。満車だけがロック内で判定され、行を書く。**「満車の不成立は後から再確認できる」は封印受入試験 [6.5][U-07]（tests/acceptance/03_idempotency.test.js）が守っている**ので、サーバーだけで消せない
- 选项: ①`withLock_` の待ち15秒を短くする（正当利用者のBUSYを増やさない範囲。実機での待ち実測後に判断）②テスト担当が U-07 を「満車の再確認は CacheService 経由（6時間）でもよい」に書き直せば、FULL行をロック前に断れる（＝燃料ゼロ）。**どちらにするかは人判断**
- 判断に効く実測（済）: ゴミ申込24本同时→正当15秒待ちBUSY（本体計測）。実機 GAS の quota で攻撃は自然に頭打ちになる可能性 → REAL_TEST の T09/T15 で測る

## P-7 通知の公平性（PT-C6の正体。解禁時判断）
- PT-C6の失敗は「攻撃者の確定行が通知 job（10件ずつ処理）で先行し、被害者（正当住民）の前日案内が当日遅れる」という公平性の問題。メールはオプション運用（G4許容・D-042）の下では優先度低。解禁時に「1人あたりの1日送信上限」か「予約順ではなく利用日順の処理」かを選ぶ
